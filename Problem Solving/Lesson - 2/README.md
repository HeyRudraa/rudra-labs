# Module 2 — Problem Solving

## Lesson 02 — Building a Flexible Problem-Solving Process

This lesson focused on developing a flexible approach to solving programming problems rather than relying on a rigid checklist.

### What I Learned

* Understand that problem solving is a **flexible process**, not a fixed sequence of steps.
* Choose the **right amount of structure** based on the complexity and familiarity of a problem.
* Distinguish between:

  * **Problem understanding**
  * **Strategy**
  * **Implementation**
* Identify the important **state, information, and relationships** needed to solve a problem.
* Use examples and edge cases to **test whether a proposed approach is actually valid**.
* Recognize the difference between a **requirement, an assumption, and a decision**.
* Use external tools such as notes, examples, or diagrams when they improve reasoning, rather than using them automatically.
* Adapt the problem-solving process when the initial interpretation or approach turns out to be incorrect.

### Core Problem-Solving Model

A useful mental model developed in this lesson was:

**Understand → Extract → Model → Design → Test → Implement → Verify → Improve**

This is treated as a flexible framework rather than a mandatory checklist.

### Key Principle

> **The goal is not to follow a checklist.
> The goal is to recognize what kind of thinking the problem requires.**

### Demonstrated Capability

By the end of the lesson, I was able to approach unfamiliar problems by:

* identifying relevant information,
* modeling required state,
* considering possible approaches,
* testing assumptions,
* validating a strategy before implementation,
* and adapting the approach when the original interpretation was incorrect.
