# 🧠 Module 2 — Problem Solving

> **Python → Problem Solving → Data Structures & Algorithms**

Module 2 is the second stage of my long-term software engineering journey.

The goal of this module is **not to learn more Python syntax**.

The goal is to become better at taking an unfamiliar problem, understanding it, reasoning about it, designing a solution, implementing it, testing it, debugging it, and eventually solving it independently.

---

## 🎯 Module Purpose

The core transition of this module is:

> **“I know Python syntax.”**

to:

> **“I can take an unfamiliar problem and figure out how to solve it.”**

The focus is on developing **problem-solving ability**, rather than simply memorizing programming patterns.

---

## 🧩 What I Will Develop

Throughout this module, I will progressively strengthen my ability to:

* Understand problems and requirements
* Identify inputs and outputs
* Identify constraints
* Decompose problems into smaller parts
* Identify relevant state
* Choose useful representations
* Develop solution strategies
* Think algorithmically
* Test assumptions
* Trace reasoning and execution
* Debug both code and reasoning
* Compare different approaches
* Explain why a solution works
* Handle edge cases
* Solve unfamiliar problems independently

---

## 🔄 Problem-Solving Model

When appropriate, I will approach problems through:

> **Problem → Requirements → Inputs → Outputs → Constraints → State → Strategy → Implementation → Testing**

This is a reasoning framework, not a rigid template that must be used for every small problem.

---

## 🐞 Debugging Model

Debugging will not be limited to syntax or code errors.

I will also learn to debug my **reasoning**.

The general model is:

> **Observed Behavior → Hypothesis → Test → Evidence → Correction → Re-test → Explanation**

A program can be syntactically correct while the underlying strategy is still wrong.

---

## 🧠 Learning Philosophy

This module follows an active-learning approach.

### WHY before HOW

For important concepts, I should understand:

1. What problem does this idea solve?
2. Why does it matter?
3. When is it useful?
4. How does it work?
5. How can I apply it?

### Think before seeing the solution

I should get a reasonable opportunity to:

* Think
* Make assumptions
* Attempt a solution
* Make mistakes
* Test my ideas
* Debug my reasoning

Solutions should not be revealed immediately when independent reasoning is possible.

### Deep understanding, not premature advanced material

The goal is to understand the ideas deeply without unnecessarily moving into future modules.

---

## 🧪 Challenge Progression

The difficulty should gradually increase:

> **Guided Practice**
>
> ↓
>
> **Cumulative Challenges**
>
> ↓
>
> **Unfamiliar Problems**
>
> ↓
>
> **Independent Solution Design**

The important question is not:

> “Can I repeat a problem I have already seen?”

It is:

> **“Can I figure out what to do when I have not seen the exact problem before?”**
